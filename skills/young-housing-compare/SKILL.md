# 청년주택 비교·추천 (young-housing-compare)

## 1. 역할 정의

이 스킬은 **이미 검토 대상이 된 공고/주택내역 안의 실제 선택지를 비교**하는 도구다.

- 공고 유형(행복주택/매입임대/전세임대 등)을 새로 제안하지 않는다. 이미 검토 대상이 된 것 안에서만 비교한다.
- 자격 자체를 새로 판정하지 않는다. 사용자가 제공한 기존 자격 판정 결과 또는 자격 상태를 그대로 사용한다.
- 자격이 없으면 임의로 판정하지 않고 "확인 필요"로 두거나 사용자에게 자격 결과를 요청한다.
- 핵심 목적은 사용자를 대신해 무조건 결정하는 것이 아니라, 여러 신청 가능한 선택지 중 무엇이 왜 더 적합한지 비교해 의사결정 시간을 줄이는 것이다.

따라서 이 스킬은 다음 2단계로 쓴다.

1. 자격 판정 단계: 별도 자격 판독, 공고 확인, 자격 요건 검토
2. 선택 비교 단계: 이 스킬 — 이미 신청 가능한 것으로 확인된 실제 주택/모집단위/호실 중에서 최적 후보를 비교

자격 결과가 없으면 이 스킬은 1순위로 "자격 결과가 필요하다"고 안내한다.

## 2. 입력

### 2.1 필수 입력

- 공고 PDF 또는 공고 내용, 또는 둘 다(공고 PDF + 주택내역 표)
- 사용자 자격 판정 결과: 주택/공고별 신청 가능/신청 불가/확인 필요, 또는 최소한 자격 Tier 정보
- 비교 대상 실제 선택지: 주소·건물·모집단위·호실 단위로 식별된 주택/그룹 목록
- 우선순위/중요도: 월 비용·보증금·면적·입주 시기 등 상대적 중요도. **필수 확인 항목.** 이 스킬은 지도·교통·통근시간·거리·가장 가까운 역 등 위치/지도 확인이 필요한 조건은 비교 우선순위에서 다루지 않는다. "우선순위 없음 / 잘 모르겠음"도 유효 응답이며, 이 경우 균형형 기본 가중치로 진행한다. 한 번 확정되면 사용자가 명시적으로 우선순위 변경을 요청하기 전까지는 다시 묻지 않는다.
- 우선순위 해석 방식: 사용자가 "A, B, C 순으로 중요해"처럼 진술하면, 이는 단순 나열이 아니라 **무엇이 더 중요한지(상대적 중요도)**로 해석한다. 이 진술을 곧바로 고정 정렬 순서로 바꾸지 않는다.
- 각 비교 항목에는 **값이 낮을수록 좋은 방향**과 **값이 높을수록 좋은 방향**이 있다. 우선순위 반영 시 이 방향을 함께 사용한다.
  - 낮을수록 좋은 항목(값이 작을수록 유리): 월세, 보증금, 월 고정비
  - 높을수록 좋은 항목(값이 클수록 유리): 면적, 입주 시기(빠를수록 유리)
  - 방향이 애매하거나 사용자 지정이 필요한 항목(면적 등)은 사용자 지정 방향을 우선하고, 지정이 없으면 위 기본 방향을 적용한다.
- 우선순위 진술에서 항목별 방향을 따로 말하지 않아도 위 기본 방향을 적용해 비교한다. 단, 사용자가 반대로 지정한 경우(예: "면적은 작아도 괜찮아", "보증금은 올릴 수 있어")에는 사용자 지정을 우선한다.

### 2.2 선택 입력

- 선호/절대 조건: 최대 보증금, 최대 월 고정비, 최소 면적, 기타 절대 제외 조건. 최대 통근시간은 **절대조건 필터용 상한**으로만 참고하며, 통근시간 자체는 사용자 직접 입력으로 확보한다.
- 보증금-월세 전환 적용 여부: 전환형이면 전환 조합까지 비교
- 이미 확보된 통근/관리비 값(있다면): 통근은 사용자 직접 계산값, 관리비는 확인된 값만 사용

> 공고 PDF와 주택내역 표가 따로 들어올 수 있다. 역할은 나눈다.
> - 공고 PDF/내용: 신청 구조, 마감일, 자격요건, 보증금-월세 전환 규칙, Tier별 조건 등
> - 주택내역 표: 주택별 주소, 비용, 면적, 호실, 주택군, 승강기 유무, 비고 등

> 입력 방식 유연화: 공고 PDF 외에 이미 추출된 텍스트·표·스프레드시트 형태의 주택 목록도 받는다.
> 추출이 불충분하면 "어떤 정보를 더 채우면 되는지"를 안내한다.

## 3. 선택지 분해와 현재 선택 단위 정의

### 3.1 공고 구조 파악

공고 자료를 읽을 때 먼저 **신청 단계에서 현재 실제로 선택할 수 있는 단위**를 확인한다.

- 단순 1개 선택형: 한 공고 안 주택 중 하나만 선택 가능 → 현재 선택 단위는 주택(호실) 단위일 수 있다.
- 모집단위(주택군) 선택형: 시·군·구 내 주택군 중 하나를 먼저 선택하고, 이후 개별 호실을 지정하는 방식 → 현재 선택 단위는 모집단위(주택군)이다. 이후 단계에서 호실을 지정한다.
- 여러 공고 동시 비교형: 공고 자체가 비교 단위일 수 있다.

공고 유형 태그는 출력과 신청 행동 순서에 반영한다.

### 3.2 주택 단위 후보 추출

- 실제 신청 가능한 주소·건물·호실 단위 주택을 각각 하나의 후보로 분해한다.
- 한 공고 안에 여러 주택이 있으면 각각 개별 후보로 본다.
- 후보 식별에는 주소 + 건물명 + 호실/주택 유형 등 구분 가능한 정보를 사용한다.
- 중복 주소/동일 주택은 하나로 합친다(명백한 중복 제거).

### 3.3 그룹화

- 같은 공고 안에서 하나만 선택 가능한 주택은 하나의 그룹으로 묶는다.
- 그룹별로 최대 신청 가능 개수를 반영한다(예: 1개, 2개 등).
- 모집단위 선택형이면 그룹 경계가 모집단위 단위로 갈릴 수 있으므로 공고 구조에 맞춘다.
- 그룹 정보와 단일선택 여부/모집단위 정보를 출력에 명시한다.
- 유사 조건 호실 그룹화: 면적·보증금·월세가 사실상 같은 선택지로 볼 수 있을 만큼 유사한 개별 호실들은 하나로 묶어 표시하거나, 그룹 안에서 대표 호실만 남기고 나머지는 "동일 조건 다수"로 요약한다. 호실 번호별로 동일한 선택지를 반복 나열하지 않는다.
  - 유사 여부 판단 기준은 공고/표의 값 해상도를 고려해 정하되, 동일한 선택지로 볼 수 있는 수준이면 묶는다.
  - 묶인 그룹은 비교표에 대표 호실과 함께 "동일 조건 N개" 같은 표시를 남긴다.
  - 다만 호실별로 주소·층·승강기·비고(소음 등)가 달라 실제 선택에 차이가 있으면 완전 동일 그룹으로 보지 않고, 차이 요인을 표에 함께 표시한다.

### 3.4 마감일/접수 방식 정리

- 각 후보/그룹에 대해 신청 마감일, 접수 방식(기간 내/선착순 등), 관련 후기 일정(순번 발표, 계약, 입주지정기간 등)을 정리한다.
- 마감 관련 정보는 신청 행동 순서에만 쓰고, 적합도 점수에는 반영하지 않는다.

## 4. 자격 처리

### 4.1 자격 구분

- 신청 가능: 현재 자격 판정 기준상 신청 가능한 후보
- 신청 불가: 현재 자격 판정 기준상 신청 불가능한 후보 → 순위 산정에서 제외
- 확인 필요: 자격이 불확실하거나 추가 확인이 필요한 후보 → 조건부 후보로 분리

### 4.2 Tier별 임대조건 처리

- 공고에 Tier별 임대조건(청년 수급자/청년 일반 등)이 있으면 사용자 자격 Tier에 맞는 행을 적용한다.
- Tier 정보가 없으면 임의로 한 행을 고르지 말고 사용자에게 확인한다.

### 4.3 순위 반영 원칙

- 신청 불가 후보는 순위에서 제외한다.
- 확인 필요 후보는 조건부 후보로 분리 표기하며, 확정 1순위로 추천하지 않는다.
- 1순위 후보가 "확인 필요" 자격이면 "이 순위는 자격 확인 전제"라는 경고를 반드시 명시한다.
- 자격 결과가 전혀 없으면 임의 판정하지 않고, 후보들을 "확인 필요"로 간주하거나 사용자에게 자격 정보 제공을 요청한다.
- 자격 정보가 없어서 모든 후보가 신청 불가로 보이면 "현재 조건으로는 신청 가능 후보가 없습니다. 확인 필요 후보를 보려면 ~ 자격 정보를 추가로 주세요" 형태로 안내한다.

## 5. 비용 비교: 월 고정비 단일 축

### 5.1 월 고정비 = 월세 + 확인된 관리비

- 비용 평가는 **월 고정비 하나의 축**으로만 비교한다.
- 월 고정비 = 월세 + (확인된 관리비).
- 월세와 관리비를 각각 독립 가중치 항목으로 두지 않는다.
- 관리비는 월 고정비 계산의 구성요소로만 사용한다.

### 5.2 관리비 미확인 처리

- 관리비가 없으면 0원으로 가정하지 않는다.
- 관리비가 미확인이면 월 고정비는 "잠정/불완전"으로 표시하고, 비용 순위가 확정적이지 않음을 알린다.
- 비교표에 "관리비 미확인"이라고 표시하고, 월 고정비 비교 시 관리비 미포함 상태임을 분명히 한다.
- "관리비가 확인되면 월 고정비 기준 순위가 바뀔 수 있다"는 점을 명시한다.
- 오피스텔·도시형생활주택 등은 관리비가 높을 수 있다는 유의사항을 참고 정보로 표시한다.

### 5.3 보증금

- 보증금은 월 고정비와 **별도 축(초기 자금 부담)**으로 유지한다.
- 보증금 증액 전환 가능 조합은 비교표에는 보여주되, 점수 계산 자체는 기본 보증금 기준 값을 사용한다.
- 보증금을 점수 축에 포함할지, 가중치/반영 방식은 사용자 선호/자금 사정에 따라 조정한다(필요하면 우선순위 입력으로 반영).

### 5.4 공과금 제거

- 공고에 공식 정보가 있거나 사용자가 직접 입력한 경우가 아니면, 전기·가스·수도 등 공과금을 임의 추정해 월 고정비에 포함하지 않는다.
- 공과금은 참고정보로만 두고, 미확인이면 미확인으로 표시한다.

### 5.5 보증금-월세 전환형 계산 절차

전환형이면 각 주택별로 가능한 조합별 월 고정비를 계산해 비교표에 제시한다. 계산 절차:

1. 기본 보증금(기본 임대조건)과 기본 월임대료를 기준으로 시작한다.
2. 주택별 최대 전환 가능 보증금과 그에 대응하는 월임대료 하한을 확인한다.
3. 사용자 지정 보증금 상한이 있으면 실제 증액 가능한 상한 = min(주택별 최대전환보증금, 사용자 보증금 상한).
4. 증액 단가와 환산율을 적용한다. 공고에 제시되어 있으면 그에 따른다(예: 10만 원 단위 증액, 연 6% 전환 가정 시 월세 감소분 = 증액분 × 6% ÷ 12). 단가·환산율이 없으면 공고 기준을 우선 확인하고, 없으면 임의로 산식·금리를 가정하지 않는다.
5. 월임대료는 주택별 월임대료 하한 이하로 낮출 수 없다. 월임대료 하한에 도달하는 지점까지만 보증금을 올린다.
6. 가능한 조합(기본/증액/하한 도달 조합)을 표로 보여준다.
7. 보증금은 월 비용과 별도 축으로 유지한다.

## 6. 교통·지도·역·통근시간 안내 방식

이 스킬은 **교통·거리·가장 가까운 역·통근시간을 조회하거나 추정하지 않는다.** 지도 기반 정보가 필요한 질문은 이 스킬에서 답하지 않는다.

### 6.1 기본 원칙

- 이 스킬은 주거지에서 회사까지의 대중교통 거리, 가장 가까운 지하철역, 도보거리·도보시간, 통근시간 등을 자동으로 계산하지 않는다.
- 사용자가 특정 주소를 제시하며 "여기까지 대중교통으로 거리가 어떻게 되나요?", "가장 가까운 역이 어디인가요?", "통근시간이 어떻게 되나요?"처럼 물으면, 이 스킬은 직접적인 계산·조회 결과를 제공하지 않는다.

### 6.2 지도 기반 질문 응답

- 교통·거리·역·통근시간 관련 질문이 들어오면, 다음 문구에 따라 정중하게 안내한다.
  - "해당 질문은 카카오맵 또는 네이버 지도에서 직접 확인하시는 것이 가장 정확합니다."
- 사용자가 직접 확인한 통근시간, 가장 가까운 역, 도보 접근 정보 등을 알려주는 경우에는 참고 정보로 받을 수 있다. 다만 이 스킬이 그 값을 대신 찾아주거나 추정하지는 않는다.

### 6.3 미확인 처리

- 교통·역·통근시간 정보가 없으면 "교통 미확인"으로 두고, 임의 추정하지 않는다.
- 교통이 미확인이어도, **우선순위와 절대조건이 확보된 상태**라면 월 비용·보증금·면적·입주 시기 등 위치/지도 확인이 필요 없는 항목 기준으로 추천 순위를 제시할 수 있다.
- 우선순위·절대조건이 미확인이면 교통 확인 여부와 관계없이 추천 순위를 제시하지 않는다.
- 교통·역·통근시간이 확정되면 결과가 달라질 수 있다는 점은 필요에 따라 안내한다.

### 6.4 우선순위 질문에서의 제외

- 우선순위/중요도를 확인할 때 통근시간, 거리, 가장 가까운 역, 도보거리·도보시간, 역 접근성 등 위치/지도 확인이 필요한 조건은 질문하지 않는다.
- 우선순위 질문은 월 비용, 보증금, 면적, 입주 시기 등 지도 없이도 판단 가능한 항목을 중심으로 진행한다.

## 7. 점수 계산 (결정론적 규칙)

상세 계산 규칙은 `references/scoring-rules.md`에 고정한다. 아래는 요약이다.

### 7.1 평가 항목과 기본 가중치 (숫자 고정)

우선순위가 "없음 / 잘 모르겠음"으로 확정되면 아래 균형형 기본 가중치를 사용한다. 같은 입력에는 항상 같은 기본 가중치를 사용한다. 사용자가 우선순위를 직접 제공하면 이 기본값을 덮어쓴다. 우선순위를 제공하지 않은 상태로 진행한 경우, 결과 출력에 "우선순위 미제공 → 균형형 기본 가중치(월 고정비 0.30 / 보증금 0.10 / 면적 0.10 / 입주 시기 0.10)로 진행"했음을 함께 표시한다.

| 평가 항목 | 기본 가중치 |
|---|---|
| 월 고정비 (월세 + 확인된 관리비) | 0.30 |
| 보증금 (별도 축) | 0.10 |
| 면적 | 0.10 |
| 입주 시기 | 0.10 |

합계 0.60. 우선순위가 들어오면 이 기본값을 덮어쓴다.

### 7.2 우선순위 반영 방식

- 사용자 우선순위를 받으면, 이를 **항목별 가중치(또는 순차 반영 우선순위)**로 변환해 점수에 반영한다. "A, B, C 순으로 중요"는 A를 가장 크게, B를 그다음, C를 그다음 반영하는 방식으로 해석한다.
- 우선순위를 **고정된 정렬 순서**로 바꾸지 않는다. 즉, "월세 우선"이라고 해서 무조건 월세만으로 정렬하지 않고, 우선순위를 반영한 가중합/순위 산정으로 결과를 낸다.
- 다만 동일한 우선순위 하에서 세부 정렬이 필요할 때는 **항목별 방향**을 따른다(7.3 항목별 점수화 개요의 방향 참조). 예: 월세 우선 맥락에서도 월세 값이 낮을수록 상위에 배치되도록 한다.
- 우선순위가 겹치거나 미묘하면 "이 우선순위로 계산하면 이런 차이가 난다" 수준으로 설명하고, 필요하면 1순위 후보 중심으로 압축해 제시한다.
- 이 스킬은 위치/지도 확인이 필요한 조건(통근시간, 거리, 가장 가까운 역, 도보거리·도보시간, 역 접근성 등)을 우선순위 비교 항목으로 다루지 않는다. 우선순위 질문은 월 비용·보증금·면적·입주 시기 등 지도 없이도 판단 가능한 항목을 중심으로 진행한다.

### 7.3 항목별 점수화 개요

각 항목은 0~100점으로 점수화하고, 최종 적합도 점수 = 가중합으로 계산한다. 상세 함수/임계값은 `references/scoring-rules.md`를 따른다. 아래는 규칙의 방향만 정리한다.

- 월 고정비: 값이 작을수록 높은 점. 관리비 미확인이면 월 고정비는 "잠정"으로 표시하고 비용 순위 확정 아님 표시.
- 보증금: 값이 작을수록 높은 점(별도 축). 증액 조합표는 비교표용 정보로 유지하고 점수 계산에는 기본 보증금 기준 값 사용.
- 면적: 값이 클수록 높은 점. 미확인이면 0점 처리 + "면적 미확인" 표시.
- 입주 시기: 빠를수록 높은 점. 미확인이면 중간값 처리 + "입주 시기 미확인" 표시.
- 통근시간·가장 가까운 역·역 접근성은 이 스킬에서 조회·추정하지 않으며, 점수 항목으로도 사용하지 않는다. 사용자가 직접 확인한 교통 정보를 참고 정보로 제공할 수는 있으나, 그 값으로 점수를 산정하지 않는다.

### 7.4 접전 후보 판단 기준 (수치 고정)

- 1위와 2위의 최종점수 차이가 **5.0점 이하**이면 "접전 후보"로 표시한다.
- 접전이면 "무엇이 선택을 바꿀 수 있는지"(관리비 확인 시, 보증금 증액 조합 차이, 면적 차이 등)를 함께 안내한다.
- 접전이어도 통근·관리비·자격 같은 핵심 정보가 미확인이면 확정 추천처럼 표현하지 않는다.

### 7.5 미확인 값 처리 원칙

- 관리비 미확인 → 월 고정비 "잠정", "관리비 미확인" 표시, 비용 순위 확정 아님 표시
- 면적 미확인 → 면적점수 0점, "면적 미확인" 표시
- 입주 시기 미확인 → 중간값 처리, "입주 시기 미확인" 표시
- 자격 "확인 필요" → 점수는 계산하되 1순위 후보로 확정 추천하지 않음, "자격 확인 전제" 명시
- 자격 정보 부재 → 임의 판정 금지, 사용자에게 자격 결과 요청 또는 "확인 필요"로 둠
- 통근시간·가장 가까운 역 등 교통/지도 정보는 이 스킬에서 조회·추정하지 않으며, 점수 항목으로도 사용하지 않는다. 해당 정보가 필요하면 사용자가 직접 확인해 알려줄 수 있고, 그 경우 참고 정보로만 다룬다.

### 7.6 동일 입력 동일 결과 원칙

- 같은 공고 자료 + 같은 자격 상태 + 같은 회사 위치 + 같은 절대조건 + 같은 우선순위가 들어오면, 같은 기본 가중치, 같은 점수 함수, 같은 접전 기준으로 계산한다.
- 사람의 판단 개입으로 숫자를 바꾸지 않는다.
- 미확인 값은 추정으로 메우지 않고 위 규칙대로 0점/중간값 처리하거나 미확인 표시를 남긴다.

## 8. 절대조건 필터 (점수 계산 전에 적용)

상세 규칙은 `references/absolute-filters.md`에 고정한다. 아래는 요약이다.

### 8.1 필터 순서

자격 적용(신청 불가 제외, 확인 필요 분리) 이후, **절대조건 필터를 먼저 적용**하고 남은 후보로 점수 계산을 한다.

### 8.2 항목별 필터 규칙

- 최대 보증금: 사용자가 "보증금 X원 초과면 무조건 제외"를 명시하면 그 기준을 절대조건으로 반영. 단순 "자금 부담" 정도면 별도 축으로 유지.
- 최대 월 고정비: 월 고정비 = 월세 + 확인된 관리비. 관리비가 미확인이면 월 고정비는 확정값이 아니므로, "월 고정비 상한 초과"로 무조건 제외하지 않는다. 대신 "관리비 미확인이라 월 고정비 확정 불가" 상태로 두고, 월세 기준 잠정 평가 + 확인 필요 표시로 처리. 사용자가 월세 기준 최대치를 준 경우에도 관리비 확인 시 기준이 초과될 수 있음을 함께 알린다.
- 최대 통근시간: 이 스킬은 통근시간을 확인하지 않으므로 최대 통근시간 조건은 적용하지 않는다. 관련된 기준은 사용자가 직접 판단해야 한다.
- 최소 면적: 전용면적이 사용자 최소 면적 미만인 후보는 제외. 면적 미확인이면 제외하지 않고 "면적 미확인"으로 둔다.
- 기타 절대 제외 조건(지역 제외, 승강기 필수, 방 개수 최소, 특정 주택유형 제외 등): 사용자 명시 조건 적용. 모호하면 확인 요청.

### 8.2.1 지역 우선순위 처리

- 사용자가 특정 지역(예: "용인을 우선", "수원 먼저")을 선호한다고 명시하면, 해당 지역 후보군을 먼저 배치한다.
- 지역 우선순위가 명시되어 있으면, 그 지역 안에서 조건 충족 후보가 부족하거나 없을 때에 한해 그다음 선호 지역 또는 전체 지역을 비교 대상으로 확장한다.
- 지역 우선이 명시되어 있지 않으면 지역을 별도 우선 기준으로 적용하지 않는다.
- 지역 우선순위는 "무엇을 먼저 보여줄지"의 표시 순서에도 반영하되, 점수 자체를 지역만으로 올리지 않는다.

### 8.3 결과 처리

- 모든 후보가 절대조건을 위반하면 "조건을 만족하는 후보 없음"으로 안내하고, 필요하면 조건 완화 여부 또는 확인 필요 후보 기준을 요청한다.
- 절대조건 위반 후보를 적합도 점수로 살려내지 않는다.
- 절대조건 통과 후보 수가 너무 많으면 우선순위 가중치로 압축하고 그 기준을 한 줄로 밝힌다.

## 9. 적합도 순위와 신청 행동 순서의 분리

### 9.1 적합도 순위

- 사용자 선호와 조건 기준으로만 산정한다.
- 마감일, 신청 일정, 선착순 여부는 적합도 점수에 반영하지 않는다.

### 9.2 신청 행동 순서

- 마감일, 신청 일정, 선착순 여부 등을 반영해 **무엇부터 처리할지**만 알려준다.
- 예: "적합도 1순위는 A이지만 B의 마감이 더 빨라 B 공고의 서류 확인을 먼저 해야 함"처럼 표현할 수 있다.

### 9.3 마감 임박 시 권고 제한

- "마감이 임박했으니 일단 신청부터 하라"는 식의 권고는 하지 않는다.
- 먼저 해당 공고의 다음 사항을 확인해 안내한다.
  - 중복 신청 가능 여부
  - 신청 후 수정 가능 여부
  - 신청 취소 가능 여부
  - 선택 단위 변경 가능 여부
- 되돌릴 수 없는 신청이면 순위 확정 전 임의 신청을 권하지 않는다.
- 마감일은 적합도 점수가 아니라 행동 순서에만 반영하는 원칙을 유지한다.

## 10. 현재 선택 단위와 후속 선택 단위의 구분

### 10.1 현재 선택해야 하는 것

- 현재 신청 단계에서 실제로 선택할 수 있는 단위로 추천한다.
- 예: 모집단위 선택형 공고면 현재 추천은 모집단위 수준.

### 10.2 후속 선택 단계 참고 후보

- 현재 단계에서 실제 선택할 수 없는 더 세부적인 단위는 "후속 선택 단계 참고 후보"로 분리해 제시한다.
- 예: 지금은 주택군만 선택하고 호실은 나중에 지정하는 구조라면, 현재 추천 결과는 주택군 수준에서 제시하고, 호실 수준 추천은 "후속 선택 단계 참고 후보"로 분리한다.

### 10.3 출력 구분 예시

- 현재 추천: A 모집단위
- 후속 호실 후보(참고): A-101, A-203, A-305
- 지금 선택해야 하는 것: A 모집단위
- 나중에 선택할 수 있는 것: A 모집단위 안에서 개별 호실

공고가 모집단위 선택형이면 최종 선택 후보를 말할 때 어느 모집단위를 선택하는지 + 그 안에서 어느 호실을 고르는지(가능한 경우)를 함께 명시한다.

## 11. 정보 신뢰도와 출처 표시

### 11.1 정보 신뢰도 등급

후보별로 정보 신뢰도를 아래처럼 표시할 수 있다.

- 높음: 순위 키에 해당하는 핵심 값(통근, 월 고정비, 자격, 면적, 입주 시기, 역 접근성 등)이 확인됨
- 중간: 일부 핵심 값이 미확인이거나 잠정 값(월세만 확정, 관리비 미확인 등)으로 계산됨
- 낮음: 순위 키에 해당하는 값이 여러 개 미확인이거나, 자격/통근/관리비/입주 시기 등 주요 정보가 부족함

### 11.2 핵심 값 출처 표시

가능하면 다음 항목은 어디에서 가져왔는지 결과를 남긴다. 최종 비교표에 별도 "근거/출처" 열을 두거나 핵심 값 옆에 출처를 표시한다.

- 신청 구조: PDF/공고 내용
- 마감일/접수 방식: PDF/공고 내용
- 보증금/월세/최대전환 조건/면적: 주택내역 표 또는 PDF
- 보증금-월세 전환율/전환 규칙: PDF 전환 산식 또는 표 전환 항목
- 자격 Tier: 공고 자격조건/표 Tier 구분
- 사용자가 직접 말한 선호/절대조건: 사용자 입력
- 미확인: 공고/표/지도/사용자 입력 어디에서도 확인되지 않음

### 11.3 미확인 값 표현 규칙 (고정)

- 통근시간, 관리비, 자격, 입주 시기처럼 순위에 큰 영향을 주는 값이 미확인이면 확정 추천처럼 표현하지 않는다.
- 미확인이 있으면 다음을 남긴다.
  - 어떤 항목이 미확인인지
  - 그 항목이 확정되면 순위가 바뀔 가능성이 있는지
  - 무엇을 추가로 받으면 되는지

예시:
- "월 고정비는 관리비 미확인이므로 잠정 비교입니다. 관리비가 확인되면 비용 순위가 바뀔 수 있습니다."
- "자격이 확인 필요 상태이므로, 이 순위는 자격 확인 전제입니다."

### 11.4 확인이 필요한 정보 목록

결과에 "확인이 필요한 정보" 목록을 따로 제시한다. 다음 포함:
- 미확인 항목
- 순위 변동에 영향을 줄 수 있는 항목
- 공고 PDF/표 간 충돌 가능성이 있는 항목

## 12. 출력 형식

출력은 다음 요소로 구성한다. 순서대로 정리한다.

### 12.1 현재 선택 단위 기준 추천 (적합도 1순위 및 대안)

- 적합도 기준 1순위 후보를 현재 선택 단위 기준으로 명시한다.
- 자격 상태에 따라 "확인 필요 전제" 여부를 함께 표기한다.
- "왜 1순위인지"를 항목별로 짧게 설명한다.
- 2~3순위 대안을 제시한다. 각 대안별로 "1순위 대비 어떤 점이 낫고 어떤 점이 아쉬운지"를 간결히 설명한다.
- 접전이면 2순위도 "접전 후보"로 표시한다.
- 동일·유사 조건 호실은 반복 나열하지 않는다. 면적·보증금·월세가 실질적으로 같은 선택지를 여러 호실 번호로 따로 추천하지 말고, 하나의 그룹 또는 대표 호실로 요약해 제시한다.
- 그룹 표시가 필요한 경우, 대표 호실과 함께 "동일 조건 N개" 정도로 압축해 표기하고, 그룹 안에서 실제로 차이가 나는 요소(층, 승강기, 비고 등)만 함께 보여준다.

### 12.2 후보별 비교표

비교표에는 가능한 범위에서 다음 항목을 넣는다.

- 후보 식별: 주소/건물/호실, 소속 공고, 그룹/모집단위 정보, 현재 선택 단위인지 여부
- 자격 상태(가능/불가/확인 필요), 적용 Tier(있으면)
- 월세, 관리비(미확인 표시), 월 고정비(잠정 표시 가능), 보증금(기본/증액 조합 포함 가능하면)
- 면적
- 입주 시기, 마감일/접수 방식
- 정보 신뢰도(높음/중간/낮음)
- 근거/출처(매 값마다 또는 별도 열로 표시)

동일 조건으로 묶인 그룹이 있으면 대표 행만 넣고, 묶인 호실 수와 차이 요인을 함께 표시한다. 개별 호실을 모두 나열해야 하는 경우에는 그 이유를 함께 밝힌다.

전환형이면 가능한 조합별 월 고정비 표도 함께 제시한다.

### 12.3 추천 이유

- 1순위 추천 이유를 항목별로 정리한다.
- 상충 항목이 있으면 무엇을 얻고 무엇을 감수했는지 설명한다.

### 12.4 단점/주의사항

- 1순위 후보의 단점/주의사항을 숨기지 않고 명시한다.
- 예: 관리비 미확인, 자격 확인 필요, 마감 임박, 위락시설 소음 가능성 등.

### 12.5 확인이 필요한 정보

- 미확인 항목, 순위 변동에 영향을 줄 수 있는 항목, 공고 PDF/표 간 충돌 가능성 항목을 목록으로 제시한다.

### 12.6 현재 선택 단위와 후속 선택 단계 구분

- 지금 선택해야 하는 것(현재 단위)과 나중에 선택할 수 있는 것(후속 단위)을 구분해 보여준다.
- 예: 현재 추천: A 모집단위 / 후속 호실 후보(참고): A-101, A-203 등.

### 12.7 신청 마감일 기준 행동 순서

- 적합도 순위와 별개로, 마감일을 반영한 신청 행동 순서를 제시한다.
- 공고별 신청 선택 구조가 있으면 그 단계에 맞춰 순서를 잡는다.
  예: "① 모집단위(주택군) 선택 후 신청 → ② 예비입주자 순번 발표 → ③ 선택한 모집단위 안에서 개별 호실 지정" 같은 구조면 행동 순서에도 ① 모집단위 선택 단계를 포함한다.
- 중복 신청 가능 여부, 수정 가능 여부, 취소 가능 여부, 선택 단위 변경 가능 여부도 함께 확인해 안내한다.
- "마감이 빠르다는 이유만으로 적합도 점수를 올리지 않는다"는 원칙을 지키며, 행동 순서는 처리 우선순위로만 제시한다.

### 12.8 한 공고 내 하나만 선택 가능한 경우 최종 선택 후보 명시

- 단일선택 그룹(공고)이 있으면 그 그룹 내 최종 선택 후보를 명시한다.
- 그룹 내 후보 중 신청 불가/확인 필요가 많아 유력 후보가 부족하면 "이 공고는 현실적으로 유력 후보 부족" 등의 코멘트를 추가한다.

### 12.9 적용 가중치 표기

출력 상단 또는 비교표 근처에 이번 비교에 적용한 가중치 기준을 한 줄로 표시한다. 사용자가 우선순위를 직접 제공했으면 항목별 우선순위를, **사용자가 질문을 받은 뒤 명시적으로 '우선순위 없음' 또는 '잘 모르겠음'이라고 답한 경우에 한해** "균형형 기본 가중치(월 고정비 0.30 / 보증금 0.10 / 면적 0.10 / 입주 시기 0.10)로 진행"이라고 명시한다. 우선순위·절대조건이 미확인인 상태에서는 기본 가중치를 적용한 추천 결과를 출력하지 않는다.

## 13. 예시 프롬프트 (사용자 발화 예시)

- "청년주택 공고 PDF와 내 자격 결과, 회사 위치를 줄게. 어디가 제일 나은지 비교해줘."
- "이 공고들(주택 목록) 중에서 나한테 맞는 순서대로 추천해주고, 마감일 기준 뭘 먼저 신청해야 할지도 알려줘."
- "A공고는 하나만 신청 가능한데, 그 안에서 제일 나은 주택 하나만 정해줘."
- "공고 PDF랑 주택내역 파일이 따로 있어. 청년 일반이고 회사는 강남구 이 주소야. 보증금 3천만, 월 60만, 면적 16㎡ 이상, 월비용·보증금·면적 순으로 보고, 보증금 증액 전환도 고려해줘."

## 14. 반복 규칙 요약 (강력 정의)

아래 규칙은 본문 여러 곳에서 반복하지 말고 여기서만 강하게 정의한다. 다른 장에서는 이 규칙을 그대로 따른다.

- **관리비 미확인 = 0원 처리 금지**: 관리비가 없으면 0원으로 가정하지 않고 "미확인/잠정"으로 표시한다.
- **지도·교통·역·통근시간 미처리**: 이 스킬은 지도·교통·거리·가장 가까운 역·통근시간을 조회하거나 추정하지 않는다. 관련 질문이 들어오면 "해당 질문은 카카오맵 또는 네이버 지도에서 직접 확인하시는 것이 가장 정확합니다"로 안내하고, 직접 확인하도록 한다. 이 스킬이 지도 기반 결과를 제공하는 것처럼 말하지도 않는다.
- **자격 확인 필요 = 확정 추천 금지**: 확인 필요 자격은 조건부 후보로 분리 표기하고, 확정 1순위로 추천하지 않는다. 1순위가 확인 필요면 "자격 확인 전제" 경고를 명시한다.
- **핵심 정보 부족 = 확정 추천 금지**: 통근/관리비/자격/입주 시기 등 순위 키에 해당하는 값이 미확인이면 확정 추천처럼 표현하지 않고 "정보 보강 필요"로 둔다.
- **유사 호실 과다 나열 금지**: 면적·보증금·월세가 사실상 같은 선택지를 호실별로 반복해 나열하지 않는다. 동일 조건 그룹은 묶거나 대표만 남기고, 실제 차이가 있는 요소만 표시한다.
- **우선순위 해석 원칙**: 우선순위는 단순 고정 정렬 순서가 아니라 항목별 상대 중요도와 값 방향(낮을수록/높을수록 좋음)을 함께 반영해 해석한다. "A, B 순"이라는 진술을 곧바로 고정 정렬 순서로 바꾸지 않는다. 위치/지도 확인이 필요한 조건(통근시간, 거리, 가장 가까운 역, 도보거리·도보시간, 역 접근성 등)은 우선순위 비교 항목에서 제외한다.
- **지역 우선순위 반영 조건**: 사용자가 특정 지역을 우선한다고 명시한 경우에만 그 지역부터 먼저 보여주고, 다른 지역은 해당 지역 후보가 부족할 때 비교 확장한다. 지역 우선 명시가 없으면 지역을 별도 우선 기준으로 적용하지 않는다.

## 15. 실행 방식

- 실행 순서 번호 정리를 반영: 공고 입력(1) → 우선순위·절대조건 확보(2) → 공고 구조화(3) → 자격 적용(4) → 비용·주택 조건 정리(5) → 절대조건 필터링(6) → 적합도 계산(7) → 추천 결과 산출(8) → 신청 행동 순서 산출(9).
- 1단계(공고 입력)에서는 공고 PDF/내용/표를 읽어 후보를 파악하되, 추천 순위를 제시하지 않는다.
- 2단계(우선순위·절대조건 확보)는 **필수 게이트**다. 사용자가 이미 제공했는지 먼저 확인하고, 제공하지 않았다면 반드시 사용자에게 질문한다. 이 질문에 대한 답변을 받기 전에는 3단계 이후(점수 계산·순위 산출·추천)를 진행하지 않는다.
- 우선순위·절대조건이 미확인이면 공고만 읽었거나 후보 정보를 추출한 상태에서도 월 임대료가 낮은 순 등 임의의 기준으로 먼저 추천하지 않는다. "미확인 = 없음"으로 간주하지 않는다.
- **필수 질문(고정) — 우선순위·절대조건이 미확인일 때:**

  > "추천 순위를 정하기 전에 두 가지를 확인할게요.\n  \n  월 비용, 보증금, 면적, 입주 시기 중 어떤 조건을 중요하게 보시나요? 특별한 우선순위가 없거나 잘 모르겠다면 그렇게 말씀해 주세요.\n  반드시 지켜야 하는 조건이 있나요? 예: 보증금 3,000만 원 이하, 월 고정비 60만 원 이하, 전용면적 16㎡ 이상. 없다면 '절대조건 없음'이라고 말씀해 주세요."

  이 질문에 대한 답변을 받기 전에는 추천 순위를 출력하지 않는다.
- 사용자가 "우선순위 없음" 또는 "잘 모르겠음"이라고 직접 답한 경우에만 균형형 기본 가중치를 적용한다. 사용자가 "절대조건 없음"이라고 직접 답한 경우에만 절대조건 없이 진행한다. 질문을 받기 전에는 이를 '없음'으로 간주하거나 기본 가중치를 바로 적용하지 않는다.
- 우선순위가 한 번 확정되면(직접 제공 또는 없음 확정), 사용자가 명시적으로 우선순위 변경을 요청하지 않는 이상 이후 비교에서 다시 묻지 않는다.
- 3단계(공고 구조화)에서는 공고를 주소·건물·호실/모집단위 단위로 분해하고, 중복 제거 및 그룹화를 수행한다. 공고의 신청 선택 구조(현재 선택 단위)를 먼저 확인한다. 이 단계에서는 추천 순위를 제시하지 않는다.
- 4단계(자격 적용)에서는 자격 상태(가능/불가/확인 필요)를 적용해 신청 불가 후보를 제외한다. Tier별 임대조건이 있으면 사용자 Tier에 맞는 행을 적용한다. Tier 정보가 없으면 임의 선택하지 않고 확인한다.
- 5단계(비용·주택 조건 정리)에서는 월 고정비 = 월세 + 확인된 관리비로 산정한다. 관리비는 월 고정비의 구성요소로만 사용하고, 미확인이면 0원 가정하지 않고 "미확인/잠정"으로 표시한다. 공과금은 임의 추정하지 않는다. 전환형이면 보증금 증액 조합표를 비교표용으로 정리한다(점수 계산용 기본 보증금 기준 값과 분리 유지).
- 6단계(절대조건 필터링)에서는 2단계에서 확인한 절대조건을 점수 계산 전에 적용한다. 조건을 위반한 후보는 적합도 계산에서 제외한다. 모든 후보가 위반하면 "조건 충족 후보 없음"으로 안내한다.
- 7단계(적합도 계산)에서는 2단계에서 확인한 사용자 우선순위를 가중치에 반영한다. 사용자가 명시적으로 우선순위 없음/잘 모르겠음이라고 답했을 때만 균형형 기본 가중치를 적용한다. 미확인 상태에서는 기본값을 자동 적용하지 않는다. 숫자/함수/접전 기준은 `references/scoring-rules.md` 고정.
- 8단계(추천 결과 산출)에서는 현재 선택 가능한 단위 기준으로 1~3순위를 제시한다. 추천 이유, 장단점, 미확인 정보, 근거/출처를 함께 표시한다.
- 9단계(신청 행동 순서 산출)에서는 적합도와 별개로 마감일, 접수 방식, 중복 신청·수정·취소 가능 여부 등을 반영해 무엇부터 처리할지 안내한다.

## 16. 주의사항

- 공고 PDF 파싱 결과는 품질이 들쭉날쭉할 수 있다. 추출이 불충분하면 주소·비용 단위로 사용자가 직접 채워 달라고 안내한다.
- 공고 PDF와 주택내역 표가 따로 들어올 수 있다. 두 출처의 역할(신청 구조/마감/자격/전환 산식 vs 개별 주택 주소·비용·면적)을 나눠 처리하고, 충돌이 있으면 임의 확정하지 않는다.
- 이 스킬은 공고 유형을 새로 추천하지 않는다. 이미 검토 대상이 된 공고/주택내역 안의 실제 선택지 비교만 한다.
- 이 스킬은 자격을 새로 판정하지 않는다. 자격 결과가 없으면 임의 판정하지 않고 사용자에게 자격 결과를 요청하거나 "확인 필요"로 둔다.
- 존재하지 않는 월세·관리비·통근시간을 추정하지 않는다.
- 마감이 빠르다는 이유로 적합도 점수를 올리지 않는다.
- 관리비 미확인을 0원으로 처리하지 않는다.
- 월세와 관리비를 각각 독립 가중치 항목으로 두지 않는다. 비용 평가는 월 고정비 단일 축으로 한다.
- 보증금은 월 비용과 별도 축으로 다루며, 점수 포함 여부는 신중하게 판단한다.
- 현재 단계에서 실제 선택할 수 없는 더 세부적인 단위를 최종 신청 추천 대상으로 제시하지 않는다.
- 되돌릴 수 없는 신청이면 순위 확정 전 임의 신청을 권하지 않는다.
- 출력 시 후보별 장단점을 균형 있게 제시하고, 추천에도 단점/주의사항을 함께 명시한다.
- 단순히 "가까워 보여서", "좋아 보여서" 같은 정성적 판단만으로 순위를 정하지 않는다.
- 보증금 증액 전환 계산은 공고에 제시된 단가·환산율·월임대료 하한을 우선 적용하고, 없으면 임의로 산식·금리를 가정하지 않는다.
- 면적·보증금·월세가 사실상 동일한 호실을 각각 개별 추천처럼 줄줄이 나열하지 않는다. 동일 조건 그룹은 묶어서 대표하고, 실제 차이가 있는 요소만 함께 보여준다.
- 우선순위는 단순 고정 정렬 순서가 아니라 항목별 상대 중요도와 값 방향(낮을수록/높을수록 좋음)을 함께 반영해 해석한다.
## 부록 A. 보증금 증액 전환(AMORT) 처리

이 부록은 보증금 증액 전환(보증금↔월세 전환) 기능이 있는 청년주택 공고에서, 사용자가 **보증금 증액 전환 고려 여부**를 명시했을 때 주택별 가능한 증액 조합별 월 고정비를 계산해 비교표에 제시하는 방법을 정한다.

### A.1 적용 범위

- 보증금 증액 전환 기능이 있는 공고/주택에만 적용한다.
- 보증금 증액 전환 기능이 없는 공고에는 이 부록의 표·규칙을 적용하지 않는다.
- 보증금 증액 전환 고려 여부가 사용자로부터 명시되지 않았거나 "모르겠다/확인 필요"면, 조합표를 만들지 않는다. 다만 사용자가 이후 전환 고려 의사를 밝히면 그때 만든다.

### A.2 사용자 입력: 보증금 증액 전환 고려 여부

- **선택 입력**이다. 기본값은 "미정/확인 필요"로 둔다.
- 사용자가 명시적으로 다음 중 하나로 말해야 그에 맞춰 반영한다.
  - "전환 고려" (보증금 증액 전환 조합까지 비교해 달라는 뜻)
  - "전환 미고려" (기본 보증금/월세 기준으로만 비교해 달라는 뜻)
  - "모르겠다/확인 필요"
- **"전환 고려"인 경우**: 각 주택별로 실제 가능한 증액 조합별 월 고정비 조합표를 비교표용 정보로 제시한다.
- **"전환 미고려"인 경우**: 전환 조합표를 만들지 않고, 기본 보증금/월세 기준으로만 비교한다.
- **"모르겠다/확인 필요"인 경우**: 조합표를 만들지 않되, 이후 전환 고려 의사가 확인되면 만든다.

### A.3 조합 계산의 원칙

1. **실제 값만 사용**: 공고에 제시된 보증금 증액 단가·환산율·월임대료 하한·최대 전환 가능 보증금·단계 경계 등 실제 존재하는 값만 사용한다. 공고에 없거나 불확실한 환산율·금리·정액 인하·월임대료 하한·상한을 임의로 가정하지 않는다.
2. **월 고정비 단일 축 유지**: 전환 조합표에서도 비용은 월 고정비(월세 + 확인된 관리비)로 선보인다. 월세와 관리비를 각각 독립 가중치 항목으로 두지 않는다.
3. **관리비 미확인 처리**: 관리비가 미확인이면 전환 조합 월 고정비에도 "관리비 미확인" 상태를 반영한다. 존재하지 않는 관리비 값을 넣어 조합 월 고정비를 확정하지 않는다.
4. **하한 보존**: 월임대료 하한이 존재하면 그 하한 이하의 월임대료는 나오지 않는다. 하한 도달 조합과 미달 조합을 구분해 표시한다.
5. **상한 반영**: 보증금 증액 상한이 있으면 실제 가능한 조합 상한을 넘지 않는다.
6. **기본 보증금 기준과 분리**: 전환 조합 월 고정비는 비교표용 정보이고, 점수 계산의 기준은 기본 보증금 기준 값을 사용한다. 두 값을 섞지 않는다.

### A.4 조합표 제시 방법

전환형이고 사용자가 "전환 고려"를 명시한 경우, 주택별로 다음 조합표를 비교표에 함께 제시한다.

- 각 조합 행: (보증금 수준, 해당 월임대료, 월 고정비, 비고)
- 조합 범위: 기본 보증금 조합 + 증액 조합 + 월임대료 하한 도달 조합(가능한 경우)
- 최대 증액 가능 보증금과 그에 대응하는 월임대료 하한을 확인한다.
- 사용자 지정 보증금 상한이 있으면 실제 증액 가능한 상한 = min(주택별 최대전환보증금, 사용자 보증금 상한)을 적용한다.
- 증액 단가와 환산율은 공고에 제시된 값을 사용한다. 없으면 임의로 산식·금리를 가정하지 않는다.
- 월임대료는 주택별 월임대료 하한 이하로 낮출 수 없다.
- 가능한 조합을 표로 보여주되, 실제 존재하는 조합만 보여준다.

### A.5 점수 계산과의 관계

- 점수 계산은 **기본 보증금 기준 값**을 사용한다(5장 일반 규칙 유지).
- 전환 조합 월 고정비는 비교표용 참고 정보로 제시한다.
- 점수를 전환 조합 월 고정비로 대체하지 않는다.

### A.6 표기와 주의

- 조합표는 주택별로 만든다.
- 각 조합은 (보증금, 월임대료, 월 고정비) 수준으로 나타낸다.
- 전환율이 표·산식으로 주어지면 해당 값을 그대로 사용한다.
- 오피스텔·도시형생활주택 등은 관리비가 높을 수 있다는 유의사항을 참고 정보로 표시할 수 있다.
- 관리비가 미확인이면 조합 월 고정비에도 "관리비 미확인(잠정)" 표시를 남긴다.

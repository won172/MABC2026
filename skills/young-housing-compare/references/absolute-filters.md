# 절대조건 필터 규칙

이 파일은 SKILL.md 8장에서 말하는 절대조건 필터 적용을 고정한다.
실행 순서는 `references/scoring-rules.md` 1단계와 동일하며, 자격 적용 후, 점수 계산 전에 적용한다.

## 1. 절대조건 정의

사용자가 제시한 다음 조건을 절대조건으로 본다.

- **넘을 수 없는 경계**: "이 조건이면 무조건 제외"라고 명시한 조건
- **최소/최대 경계**: 최대 보증금, 최대 월 고정비, 최대 통근시간, 최소 면적 등
- **기타 절대 제외 조건**: 특정 지역 제외, 승강기 필수, 방 개수 최소, 특정 주택유형 제외, 층수 제한 등

단, "자금 부담이 커서 보증금을 적게 보고 싶다" 같은 선호 수준은 절대조건이 아니라 별도 축으로 유지한다.

## 2. 적용 순서 (고정)

1. 자격 상태 적용: 신청 불가 후보 제외, 확인 필요 후보 분리
2. **절대조건 필터 적용**: 아래 항목별 규칙대로 위반 후보 제외
3. 남은 후보로 점수 계산 (상세: `references/scoring-rules.md`)

절대조건 위반 후보는 적합도 점수로 살려내지 않는다.

## 3. 항목별 필터 규칙

### 3.1 최대 보증금

- 사용자가 "보증금 X원 초과면 무조건 제외"를 명시한 경우 → 그 기준을 절대조건으로 반영해 초과 후보 제외.
- 단순 "초기 자금 부담이 커서 보증금을 적게 보고 싶다" 수준이면 절대조건이 아니라 별도 축(보증금 점수/가중치)으로 유지한다.
- 보증금 증액 전환 가능 여부와 무관하게, 사용자가 명시한 상한을 우선 적용한다.

### 3.2 최대 월 고정비

- 월 고정비 = 월세 + **확인된 관리비**.
- 관리비가 미확인이면 월 고정비는 확정값이 아니다.
- 따라서 관리비 미확인 상태에서 "월 고정비 상한 초과"로 무조건 제외하지 않는다.
- 대신 다음 중 하나로 처리한다.
  - 관리비 미확인이라 월 고정비 확정 불가 상태로 두고,
  - 월세 기준 잠정 평가로 본 뒤, 관리비가 확인되면 상한 초과 가능성이 있음을 함께 알린다.
- 사용자가 "월세 기준 최대치"를 준 경우에도, 관리비가 확인되면 그 기준이 초과될 수 있음을 안내한다.
- 관리비에 대한 정보가 전혀 없는데 월 고정비 상한이 매우 타이트하면, "관리비 확인이 필요해 지금 단계에서 확정 제외하기 어렵다"고 설명한다.

### 3.3 최대 통근시간

- 통근시간이 측정된 후보 중 사용자 최대 통근시간을 초과하는 후보는 제외한다.
- 통근시간이 **미확인**인 후보는 제외하지 않는다. 대신 "통근 미확인" 상태로 둔다.
- 통근 미확인 후보가 많아도, 통근정보 없이 순위를 확정하지 않는다.
- 통근 미확인 후보 중 일부라도 통근정보를 받으면 그때 다시 필터/순위를 갱신할 수 있다.

### 3.4 최소 면적

- 전용면적이 사용자 최소 면적 미만인 후보는 제외한다.
- 면적이 **미확인**인 후보는 제외하지 않는다. 대신 "면적 미확인" 상태로 둔다.
- 면적 미확인 후보가 있다면 면적정보 입력 시 다시 필터/순위를 갱신할 수 있다.

### 3.5 기타 절대 제외 조건

사용자가 명시한 다음 조건들을 적용한다.

- 특정 지역 제외
- 승강기 필수
- 방 개수 최소
- 특정 주택유형 제외
- 층수 제한
- 기타 사용자 명시 절대적 제외 조건

조건이 모호하면 사용자에게 확인을 요청한다. 예를 들어 "저층은 제외한다"처럼 범위가 불명확하면 "몇 층까지 제외인지" 확인을 요청한다.

## 4. 미확인 값과 절대조건 필터의 관계

절대조건 필터에서 미확인 값은 "무조건 제외" 근거로 쓰지 않는다.

- 통근 미확인 → 통근 상한 위반으로 자동 제외하지 않음, "통근 미확인" 표시
- 면적 미확인 → 최소 면적 위반으로 자동 제외하지 않음, "면적 미확인" 표시
- 월 고정비 미확인(관리비 미확인) → 월 고정비 상한 위반으로 자동 제외하지 않음, "월 고정비 확정 불가" 표시
- 자격 미확인/확인 필요 → 별도 절(자격 처리 규칙)에 따름

즉, 미확인 항목은 "지금은 통과/제외를 확정할 수 없는 상태"로 두고, 정보 입력 시 다시 평가한다.

## 5. 결과 처리

### 5.1 모든 후보가 절대조건을 위반하면

- "현재 조건으로는 조건을 만족하는 후보가 없습니다"라고 안내한다.
- 필요하면 다음 중 하나를 요청한다.
  - 조건 완화 여부 (예: 최대 통근시간 확대, 최소 면적 축소, 월 고정비 상한 완화 등)
  - 확인 필요 후보 기준 (미확인이어서 제외된 후보들이므로, 정보를 보완하면 다시 검토 가능하다는 안내)
  - 자격 정보 보완 (자격 미확정으로 제외됐을 가능성)

### 5.2 절대조건 통과 후보가 너무 많으면

- "절대조건만으로는 대부분 통과합니다"라고 한 줄로 밝히고,
- 우선순위 가중치(통근, 월 비용, 면적, 역 접근성 등)로 압축한다.
- 이때 사용한 기준을 함께 밝힌다.

### 5.3 절대조건 통과 후 점수 계산

- 절대조건 통과 후보만 점수 계산 대상이 된다.
- 절대조건을 위반한 후보는 적합도 점수로 살려내지 않는다.
- 접전 판단, 미확인 처리, 자격 확인 필요 표시는 이후 단계에서 적용한다.

## 6. 재확인 트리거

다음 정보가 들어오면 절대조건 필터/순위를 다시 평가해야 한다.

- 통근시간 입력(추가로 절대 통근 상한 통과/위반 후보가 바뀔 수 있음)
- 면적 입력(최소 면적 위반/통과가 바뀔 수 있음)
- 관리비 입력(월 고정비 확정값이 바뀌어 상한 위반/통과가 바뀔 수 있음)
- 자격 결과 보완(신청 불가/가능 상태가 바뀌어 필터 결과가 바뀔 수 있음)
- 사용자 절대조건 변경(상한/하한 변경 시 통과 후보 집합이 바뀜)
